# 04 堆与动态内存

> 栈适合短生命周期数据，堆适合运行时动态申请的数据。堆的问题通常不是“函数返回了”，而是“这块内存现在到底归谁”。

## 一句话

堆是一片可动态借还的内存区域：`malloc/new` 借，`free/delete` 还。借还顺序复杂时，就容易出现生命周期错误。

```mermaid
flowchart LR
    A[申请 malloc] --> B[得到堆块]
    B --> C[读写数据]
    C --> D[释放 free]
    D --> E[分配器回收或复用]
```

## 栈和堆的区别

| 对比 | 栈 | 堆 |
| --- | --- | --- |
| 管理方式 | 函数调用自动管理 | 程序员或运行时手动/半自动管理 |
| 生命周期 | 随函数进入和返回 | 从申请到释放 |
| 速度 | 通常更快 | 通常更复杂 |
| 常见问题 | 栈溢出、返回地址覆盖 | UAF、double free、堆溢出 |

```text
进程地址空间片段
┌────────────────────┐ 高地址
│ stack              │ 自动增长/回收
├────────────────────┤
│ mmap               │ 共享库、大块映射
├────────────────────┤
│ heap               │ malloc/new 动态申请
└────────────────────┘ 低地址
```

## 堆块长什么样

分配器通常不会只保存你的数据，还会保存管理信息。不同分配器细节不同，但可以这样理解：

```text
一个堆块
┌────────────────────┐
│ 元数据 metadata     │ 大小、状态、链表指针等
├────────────────────┤
│ 用户可用区域         │ malloc 返回的指针指向这里
└────────────────────┘
```

你拿到的指针通常指向“用户可用区域”，但它旁边可能就是分配器元数据或其他堆块。

## 申请和释放

```c
char *p = malloc(32);
strcpy(p, "hello");
free(p);
```

这段代码的时间线：

```text
malloc(32)
  ↓
p 指向一块可用堆内存
  ↓
写入 "hello"
  ↓
free(p)
  ↓
这块内存不再属于 p
```

`free(p)` 之后，`p` 变量本身还保存着旧地址，但那块内存已经归还给分配器了。

## Use-After-Free

UAF 是释放后继续使用。

```c
free(p);
puts(p); // 错误：p 指向的堆块已经释放
```

图像化理解：

```text
释放前
p ──────────> [ 堆块 A：属于程序 ]

释放后
p ──────────> [ 堆块 A：已归还分配器 ]

再次分配后
p ──────────> [ 堆块 A：可能属于别的对象 ]
q ──────────> [ 同一块或附近内存 ]
```

危险在于：旧指针还在，但所有权已经变了。

## Double Free

Double free 是同一块内存释放两次。

```c
free(p);
free(p); // 错误：重复释放
```

后果可能是：

- 分配器状态被破坏。
- 程序崩溃。
- 某些条件下造成可控的内存复用异常。

现代分配器通常会检测一部分重复释放，但不要依赖它救场。

## 堆溢出

堆溢出是写出当前堆块边界，覆盖相邻堆块或元数据。

```text
正常
┌──────────────┬──────────────┐
│ chunk A      │ chunk B      │
│ data[16]     │ object       │
└──────────────┴──────────────┘

写入过长
┌──────────────┬──────────────┐
│ AAAAAAAAAAAA │ AAAAA...     │ <- 覆盖到 chunk B
└──────────────┴──────────────┘
```

可能影响：

| 覆盖目标 | 可能后果 |
| --- | --- |
| 相邻对象字段 | 程序逻辑异常 |
| 指针字段 | 读写错误地址 |
| 分配器元数据 | 分配器检测失败或崩溃 |
| 函数指针/虚表指针 | 控制流风险 |

## 为什么堆更难

栈的生命周期比较规整：函数进来、函数出去。

堆的生命周期常常交错：

```text
申请 A
申请 B
释放 A
申请 C 可能复用 A 的位置
释放 B
继续误用 A 的旧指针
```

这就是堆漏洞难分析的原因：要同时看对象大小、申请顺序、释放顺序和复用关系。

## 简化的分配器视角

分配器会把释放后的堆块放进空闲列表，等待下次复用。

```text
free 后的堆块
┌────────┐     ┌────────┐     ┌────────┐
│ 空闲块 │ --> │ 空闲块 │ --> │ 空闲块 │
└────────┘     └────────┘     └────────┘
```

现代分配器会有更复杂的结构，比如 tcache、bins、fastbin 等。入门阶段先理解“释放后会被复用”就够了。

## 写代码时怎么避免

- 谁申请，谁释放；所有权要清楚。
- `free` 后把指针置为 `NULL`，减少误用。
- 不共享裸指针，尽量用智能指针或容器。
- 复制数据前检查目标大小。
- 一个对象释放后，不再访问它的字段、方法和指针。
- 开启 AddressSanitizer 等运行时检查工具。

## 小结

- 堆用于动态生命周期的数据。
- 分配器除了用户数据，还维护元数据。
- UAF 是释放后继续使用。
- Double free 是重复释放。
- 堆溢出会覆盖相邻堆块或管理信息。
- 堆漏洞的核心难点是对象生命周期和内存复用。
