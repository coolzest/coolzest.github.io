虚拟内存、物理内存与 TLB 地址转换全景图

一次普通的 mov rax, [address] 背后，CPU 会让 MMU 拆分虚拟地址、查询 TLB（快表）、 必要时遍历四级页表，检查权限，再组合物理地址并经过 CPU Cache 访问 DRAM。

虚拟地址进程看到的地址，每个进程拥有独立空间
页表映射虚拟页号 VPN → 物理页框号 PFN
页内偏移转换前后完全不变，直接拼到物理页框后

地址转换最核心的两条式子

VA = VPN × PageSize + Offset
⇒
PA = PFN × PageSize + Offset
关键直觉：页表只翻译“页号”。4 KiB 页的低 12 位是页内偏移， 无论映射到哪个物理页框，这 12 位都原样保留。

03

TLB 未命中时，四级页表如何“走”到物理页框

CR3 保存当前地址空间根页表的物理基址；每个 9 位索引选择 512 个表项中的一个。

硬件 Page Walk 展开图

每个表项 8 B · 每张表 512 项 · 恰好占 4 KiB
CR3 / 页表根 0x0000000123400000 保存 L4 页表的物理地址
→
PML4E[0x0FE] 0x00000001234007F0 读出 L3 页表物理基址
PDPTE[0x048] 0x0000000456700240 读出 L2 页表物理基址
PDE[0x1A2] 0x0000000789A00D10 读出 L1 页表物理基址
PTE[0x167] 0x0000000ABCD00B38 得到 PFN 与页面权限
→
物理页框 PFN 0x2A91B 页框基址 + Offset = PA
最坏情况四级页表读取 4 次，再访问目标数据 1 次；TLB 用来避免频繁付出这个代价。
页表项也会被缓存页表遍历读取本身会利用 CPU Cache 和专用的 paging-structure cache。
大页会缩短路径2 MiB 页可在 PDE 结束，1 GiB 页可在 PDPTE 结束，但内部碎片可能更大。

TLB 与 CPU Cache 到底差在哪

一个缓存“地址翻译”，一个缓存“实际内容”
组件缓存内容查询键未命中后
TLB / 快表VPN → PFN + 权限虚拟页号 + ASID/PCID遍历页表
L1/L2/L3 Cache指令或数据的 Cache Line地址的一部分访问下一级 Cache / DRAM
页表完整、权威的映射关系多级虚拟地址索引不存在则 Page Fault
Swap / 文件暂未驻留 DRAM 的页面内容内核记录的后备位置磁盘 I/O，延迟极高
常见误区：TLB 命中只代表“地址翻译找到了”，不代表目标数据也在 L1 Cache； 两次命中是两个不同层面的加速。
05

缺页异常不是一定“出错”

合法缺页是按需分页的正常机制；非法地址或权限冲突才会最终变成访问违规。

1. 指令访问 VACPU 发起读取、写入或取指请求。
2. TLB Miss快表中没有当前 VPN 的有效翻译。
3. PTE Present=0页表遍历发现页面当前不在物理内存。
4. 进入内核检查 VMA、访问类型与后备存储信息。
5. 准备页框分配零页、文件调页、Swap-in 或写时复制。
6. 更新 PTE/TLB写入 PFN 和权限，失效旧 TLB 项。
7. 重启原指令相同指令再次执行，这次可以完成访问。
Minor Page Fault不需要磁盘读取，例如首次分配匿名零页或写时复制；仍有内核切换成本。
Major Page Fault需要从文件或 Swap 读取，延迟通常远高于普通内存访问。
Protection Fault映射存在但权限不允许，例如写只读页或执行 NX 页；通常不能靠调页解决。

把整个体系压缩成五句话

如果这五句能在脑中连起来，虚拟内存的主干就已经建立。

1. 程序使用 VA每个进程看到自己的虚拟地址空间，而不是直接操作 DRAM 地址。
2. TLB 先加速翻译命中时直接得到 PFN 与权限；未命中才需要遍历页表。
3. 页表映射 VPN→PFN四级索引找到 PTE，页内偏移始终原样保留。
4. 异常交给 OS合法缺页可分配或调入页面；非法地址和权限冲突通常终止进程。
5. PA 再访问 Cache/DRAM翻译命中与数据命中是两件事，TLB 和 CPU Cache 各司其职。
