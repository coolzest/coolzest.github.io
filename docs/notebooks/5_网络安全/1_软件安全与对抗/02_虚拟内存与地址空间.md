# 02 虚拟内存与地址空间

> 程序里看到的地址，不是直接的物理内存地址，而是虚拟地址。理解虚拟内存，后面的栈、堆、ASLR、越界访问才会变清楚。

## 一句话

虚拟内存让每个进程都以为自己独占一大片连续内存；真正访问时，CPU 和操作系统再把虚拟地址翻译成物理地址。

```mermaid
flowchart LR
    A[程序使用虚拟地址] --> B[CPU 查询页表]
    B --> C{映射存在?}
    C -- 是 --> D[得到物理地址]
    C -- 否 --> E[触发缺页异常]
```

## 为什么需要虚拟内存

| 目的 | 解释 |
| --- | --- |
| 隔离 | 一个进程不能随便读写另一个进程 |
| 简化 | 程序看到的是整齐的地址空间 |
| 保护 | 每页可以设置读、写、执行权限 |
| 共享 | 多个进程可以共享同一份库代码 |
| 按需加载 | 用到时再分配物理内存 |

一句话：虚拟内存既是“抽象”，也是“安全边界”。

## 地址空间长什么样

典型 64 位 Linux 进程大致如下。不同系统和配置会有差异，但形状类似。

```text
高地址
┌──────────────────────────┐
│ 内核空间                 │ 用户态不可直接访问
├──────────────────────────┤
│ 栈 stack                 │ 函数调用、局部变量，通常向低地址增长
├──────────────────────────┤
│ mmap 区                  │ 共享库、匿名映射、文件映射
├──────────────────────────┤
│ 堆 heap                  │ malloc/new 动态申请，通常向高地址增长
├──────────────────────────┤
│ .bss                     │ 未初始化全局变量
├──────────────────────────┤
│ .data                    │ 已初始化全局变量
├──────────────────────────┤
│ .rodata                  │ 只读常量
├──────────────────────────┤
│ .text                    │ 程序代码
└──────────────────────────┘
低地址
```

先记方向：

- 栈常常向低地址增长。
- 堆常常向高地址增长。
- 共享库通常在 mmap 区。
- 内核空间在高地址，用户程序不能直接访问。

## 页：内存管理的基本单位

操作系统不是一个字节一个字节管理内存，而是按“页”管理。常见页大小是 4 KB。

```text
虚拟地址空间
┌──────┬──────┬──────┬──────┐
│ 页 0 │ 页 1 │ 页 2 │ 页 3 │
└──────┴──────┴──────┴──────┘
   │      │             │
   ▼      ▼             ▼
物理内存中的页框
┌──────┬──────┬──────┬──────┐
│ 框 A │ 框 B │ 框 C │ 框 D │
└──────┴──────┴──────┴──────┘
```

页表记录两件事：

| 信息 | 作用 |
| --- | --- |
| 映射 | 这个虚拟页对应哪个物理页 |
| 权限 | 这页能不能读、写、执行、用户态访问 |

## 访问内存时发生什么

程序执行 `mov rax, [addr]` 这类指令时，大致发生：

1. CPU 拿到虚拟地址。
2. MMU 查询页表。
3. 如果映射存在且权限允许，就访问物理内存。
4. 如果映射不存在或权限不允许，就触发异常。

```text
正常访问：地址存在 + 权限允许 -> 读写成功
越界访问：地址不存在          -> Segmentation fault
权限错误：写只读页 / 执行不可执行页 -> Segmentation fault
```

所以崩溃不只是“程序坏了”，它常常是在告诉你：访问的地址或权限不对。

## 内存权限

每个映射区域都有权限：

| 权限 | 说明 | 常见区域 |
| --- | --- | --- |
| `r--` | 只读 | 只读常量 |
| `r-x` | 可读可执行 | 代码段、共享库代码 |
| `rw-` | 可读可写 | 栈、堆、数据段 |
| `---` | 不可访问 | 保护页、未映射区域 |

安全原则很简单：能不写就不写，能不执行就不执行。

## ASLR：地址随机化

ASLR 会让程序每次运行时的关键区域地址变化。

```text
第一次运行：libc 在 0x7f12....
第二次运行：libc 在 0x7f88....
第三次运行：libc 在 0x7fa3....
```

它的目的不是隐藏程序逻辑，而是让攻击者难以猜到：

- 栈在哪里。
- 堆在哪里。
- 共享库在哪里。
- 可复用指令片段在哪里。

如果存在信息泄露漏洞，攻击者可能先读出一个地址，再推算其他地址。所以“信息泄露”会削弱 ASLR。

## 进程隔离

两个进程可以使用相同的虚拟地址，但映射到不同物理内存。

```text
进程 A: 0x400000 ──> 物理页 X
进程 B: 0x400000 ──> 物理页 Y
```

这就是为什么一个普通程序不能随便读另一个程序的变量。必须通过系统调用、共享内存、文件、管道、Socket 等受控方式通信。

## 和安全的关系

| 机制 | 安全意义 |
| --- | --- |
| 页权限 | 阻止数据页直接执行，阻止代码页被修改 |
| 进程隔离 | 限制漏洞影响范围 |
| ASLR | 增加利用时猜地址的难度 |
| 缺页异常 | 让非法访问尽早暴露 |
| mmap | 文件解析、共享库、JIT 都常涉及它 |

## 快速观察

在 Linux 中可以看进程内存映射：

```bash
cat /proc/<pid>/maps
```

你会看到类似：

```text
00400000-00401000 r-xp ... /path/a.out
00601000-00602000 rw-p ... /path/a.out
7f....-7f....     r-xp ... libc.so
7fff....-7fff.... rw-p ... [stack]
```

重点看三列：地址范围、权限、属于哪个文件或区域。

## 小结

- 程序使用的是虚拟地址，不是直接物理地址。
- 页表负责把虚拟地址翻译到物理内存。
- 页权限决定一片内存能不能读、写、执行。
- 栈、堆、代码段、共享库都在同一个进程地址空间里。
- ASLR、NX、进程隔离都建立在虚拟内存机制之上。
