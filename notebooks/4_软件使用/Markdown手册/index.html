    Markdown 手册¶

    Markdown 的目标不是“炫技”，而是用尽量少的标记写出结构清晰、方便阅读、方便维护的文档。写 Markdown 时，先想清楚文章结构，再补充格式。

    一页速查¶

    目标 写法 效果/说明
    一级标题 # 标题 页面主标题，一篇文章通常只写一个
    二级标题 ## 标题 章节标题
    加粗 **重点** 重点
    斜体 *强调* 强调
    删除线 ~~删除~~ 删除
    行内代码 `printf()` printf()
    链接 [名称](https://example.com) 名称
    图片 ![描述](image.png) 插入图片
    无序列表 - 条目 常用项目列表
    有序列表 1. 条目 步骤、流程
    引用 > 内容 引用、说明、摘录
    分割线 --- 分隔大段内容
    任务列表 - [ ] 待办 勾选清单
    表格 | 列1 | 列2 | 对齐信息
    脚注 文字[^1] 补充说明
    转义 \* 显示 Markdown 符号本身

    基本写作规则¶

    Markdown 文档最好遵守这几个习惯：

    1. 标题负责结构，不负责装饰。
    2. 空行负责分段，不要把很多内容挤在一起。
    3. 列表适合并列信息，表格适合对比信息，代码块适合命令和程序。
    4. 图片必须写清楚替代文本，方便搜索和理解。
    5. 一篇文章只用一个一级标题 #，后面用 ##、### 分层。
    6. 文件名尽量稳定，不要频繁改动，否则站内链接容易失效。

    标题¶

    标题用 # 表示，# 越多，层级越低。

    1
2
3
4
5
6
    # 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题

    推荐用法：

    • #：文章标题。
    • ##：主要章节。
    • ###：章节里的小节。
    • ####：只有内容确实很复杂时再用。

    不要为了让字变大就乱用标题。标题的本质是文章大纲。

    段落与换行¶

    普通段落之间用一个空行分开：

    1
2
3
    这是第一段。

这是第二段。

    如果只是想在同一段里强制换行，有三种方式：

    写法 说明 推荐程度
    段落之间加空行 最自然，兼容最好 推荐
    行尾加两个空格 Markdown 原生硬换行 可用，但不明显
    <br> HTML 换行 偶尔使用

    示例：

    1
2
3
4
5
6
7
8
9
    第一行  
第二行

第一段。

第二段。

第一行<br>
第二行

    写文章时优先使用空行分段。大量 <br> 会让文档变难维护。

    文字样式¶

    写法 效果 适合场景
    **重要内容** 重要内容 强调关键结论
    *强调内容* 强调内容 轻微强调
    ***又粗又斜*** 又粗又斜 少用，容易显得乱
    ~~已删除~~ 已删除 表示废弃内容
    <u>下划线</u> 下划线 Markdown 没有原生下划线时使用 HTML

    快捷键：

    • 加粗：Ctrl+B
    • 斜体：Ctrl+I

    建议：

    • 加粗只标真正重要的词，不要整段加粗。
    • 斜体在中文文档里少用，阅读辨识度不如加粗。
    • 删除线适合记录变更，不适合表示普通否定。

    引用¶

    引用使用 >。

    1
2
3
4
    > 这是一段引用。
> 引用中可以继续换行。

正文从这里继续。

    效果：

    这是一段引用。 引用中可以继续换行。

    多层引用：

    1
2
3
    > 第一层引用
>> 第二层引用
>>> 第三层引用

    建议：

    • 引用适合放摘录、解释、提示语。
    • 引用结束后加一个空行，再继续写正文。
    • 不要把整篇文章都放在引用块里。

    无序列表¶

    无序列表用 -、* 或 +。建议统一使用 -。

    1
2
3
    - 第一项
- 第二项
- 第三项

    效果：

    • 第一项
    • 第二项
    • 第三项

    有序列表¶

    1

3
    1. 打开终端
2. 进入项目目录
3. 执行构建命令

    效果：

    1. 打开终端
    2. 进入项目目录
    3. 执行构建命令

    链接¶

    普通链接¶

    1
    [Coolzest NOTE](https://coolzest.github.io)

    效果：Coolzest NOTE

    自动链接¶

    1
    <https://coolzest.github.io>

    效果：https://coolzest.github.io

    站内相对链接¶

    同目录文件：

    1
    [Docker 使用指南](2024-08-16-Docker.md)

    上一级或子目录：

    1
    [DPDK 专题](../10_Linux开发/1_DPDK/index.md)

    建议：

    • 链接文字要写清楚，不要只写“点击这里”。
    • 站内链接尽量使用相对路径。
    • 链接到标题时，优先使用页面目录自动生成的锚点。

    图片¶

    基本写法：

    1
    ![图片描述](图片路径)

    示例：

    1
    ![DPDK 数据流示意图](assets/dpdk-flow.png)

    带标题：

    1
2
3
4
    ![DPDK 数据流示意图](assets/dpdk-flow.png)
/// caption
DPDK 数据流从网卡队列进入用户态程序。
///

    使用属性控制大小：

    1
    ![Logo](assets/logo.png){ width="160" }

    建议：

    • [] 里写图片说明，方便理解和无障碍阅读。
    • 图片文件名用英文、数字、短横线，避免空格。
    • 大图放在 docs/assets/ 或当前专题目录下的 assets/。
    • 不要直接引用容易失效的外链图片。

    效果：

    建议：

    • 分割线用于明显分隔上下两块内容。

    代码¶

    行内代码¶

    行内代码用反引号包裹：

    1
    使用 `git status` 查看工作区状态。

    效果：使用 git status 查看工作区状态。

    适合行内代码的内容：

    • 命令：mkdocs build
    • 文件名：mkdocs.yml
    • 函数名：main()
    • 配置项：theme.name
    • 环境变量：PATH

    代码块¶

    代码块用三个反引号包裹，并建议写上语言：

    1
2
3
    ```python
print("Hello Markdown")
```

    效果：

    1
    print("Hello Markdown")

    常见语言标识：

    语言 标识
    Shell bash
    Python python
    C c
    C++ cpp
    YAML yaml
    JSON json
    Markdown markdown
    文本 text

    命令示例¶

    1
2
3
    mkdocs serve
mkdocs build
python generate_nav.py --nav-only

    建议：

    • 命令、配置、代码都放代码块。
    • 代码块尽量标语言，这样会有语法高亮。
    • 不要把长段普通文字放进代码块。

    表格¶

    表格用 | 分隔列，用 --- 分隔表头和正文。

    1
2

    | 名称 | 作用 | 备注 |
| --- | --- | --- |
| `#` | 标题 | 1 到 6 级 |
| `-` | 无序列表 | 推荐统一使用 |
| `>` | 引用 | 适合说明和摘录 |

    效果：

    名称 作用 备注
    # 标题 1 到 6 级
    - 无序列表 推荐统一使用
    > 引用 适合说明和摘录

    对齐方式¶

    1
2
3
    | 左对齐 | 居中 | 右对齐 |
| :--- | :---: | ---: |
| A | B | C |

    效果：

    左对齐 居中 右对齐
    A B C

    建议：

    • 表格适合短文本对比。
    • 表格里不要塞太长段落。
    • 表格内容太多时，考虑拆成多个小表。

    任务列表¶

    任务列表用于待办和检查清单。

    1
2
3

- [x] 完成目录整理
- [ ] 检查链接

    效果：

    • 写初稿
    • 完成目录整理
    • 检查链接

    适合场景：

    • 学习计划。
    • 发布前检查。
    • Bug 修复清单。
    • 项目任务拆分。

    脚注¶

    脚注适合放补充说明，不打断正文。

    1
2
3
    Markdown 是一种轻量级标记语言[^markdown]。

[^markdown]: 它使用纯文本符号表达标题、列表、链接、代码等结构。

    效果：

    Markdown 是一种轻量级标记语言1。

    建议：

    • 正文只保留主要信息。
    • 解释来源、术语、补充细节时使用脚注。
    • 不要把重要结论放到脚注里。

    转义字符¶

    如果想显示 Markdown 符号本身，可以在前面加反斜线 \。

    想显示 写法
    * \*
    _ \_
    # \#
    [ \[
    ] \]
    ( \(
    ) \)
    \ \\

    示例：

    1
    \*\*这不会被加粗\*\*

    效果：

    **这不会被加粗**

    MkDocs 常用扩展¶

    本站使用 MkDocs Material，并开启了不少 Markdown 扩展。下面这些写法在本站尤其常用。

    提示框¶

    1
2
3
4
5

7
8
    !!! note "说明"
    这里写普通说明。

!!! warning "注意"
    这里写风险提醒。

!!! tip "技巧"
    这里写建议或捷径。

    效果：

    说明

    这里写普通说明。

    注意

    这里写风险提醒。

    技巧

    这里写建议或捷径。

    常用类型：

    类型 用途
    note 普通说明
    tip 技巧
    warning 警告
    danger 高风险
    info 信息
    example 示例
    question 问题

    可折叠块¶

    适合场景：

    • 长代码。
    • 额外解释。
    • 练习答案。
    • 不想打断主线的补充内容。

## 背景

为什么需要这篇文章。

1. 第一步

    适合用列表的内容¶

    • 多个并列概念。
    • 操作步骤。
    • 优缺点。
    • 注意事项。
    • 排查清单。

    • 命令与说明。

    常见问题¶

    为什么标题没有出现在目录里¶

    可能原因：

    • 标题前没有空行。
    • 标题格式不正确，例如写成了 ##标题，中间缺少空格。
    • 标题层级太深，超过了站点目录配置。

    正确写法：

    1
    ## 标题

    为什么列表没有正确渲染¶

    列表标记后面要有空格：

    1
2
    - 正确
-错误

    嵌套列表要缩进：

    1
2
    - 第一层
  - 第二层

    为什么代码块没有高亮¶

    通常是没有写语言：

    1
2
3
    ```bash
mkdocs build
```

    为什么表格显示不整齐¶

    Markdown 源码里的表格不一定要完全对齐，但表头分隔行必须存在：

    1
2
3
    | A | B |
| --- | --- |
| 1 | 2 |

    什么时候用 HTML¶

    Markdown 支持内嵌 HTML，但只建议少量使用：

    • 需要特殊排版时。
    • Markdown 原生语法做不到时。
    • 使用已有站点组件时。

    能用 Markdown 解决的，就优先用 Markdown。

    最后记一句¶

    好的 Markdown 文档，不是符号越多越好，而是结构越清楚越好。标题让读者知道“现在在哪里”，列表让信息更容易扫读，代码块让命令可以复制，表格让对比一眼看懂。
