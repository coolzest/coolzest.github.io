    MySQL 基础¶

    这篇按“工作时忘了就来复制”的方式整理：前面是可编辑 SQL 代码框，后面才是必要解释。

    可填空代码框¶

    写笔记时，在代码块里用 {{提示词}} 标出要填的地方，网页会自动变成可输入的小框。复制时复制的是填好后的最终代码。

    创建数据库¶

    1
2
3
    CREATE DATABASE IF NOT EXISTS `{{数据库名}}`
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

    创建表¶

    1
2
3
4
5
    CREATE TABLE `{{表名}}` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT 'ID',
  `{{字段名}}` VARCHAR(50) NOT NULL COMMENT '名称',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

    查询数据¶

    1
2
3
    SELECT {{字段列表}}
FROM `{{表名}}`
WHERE {{条件}};

    插入数据¶

    1
2
    INSERT INTO `{{表名}}` ({{字段列表}})
VALUES ({{值列表}});

    更新数据¶

    1
2
3
    UPDATE `{{表名}}`
SET {{字段 = 值}}
WHERE {{条件}};

    删除数据¶

    1
2
    DELETE FROM `{{表名}}`
WHERE {{条件}};

    创建索引¶

    1
2
    CREATE INDEX `{{索引名}}`
ON `{{表名}}` (`{{字段名}}`);

    授权¶

    1
2
3
    GRANT SELECT, INSERT, UPDATE
ON `{{数据库名}}`.*
TO '{{用户名}}'@'{{主机}}';

    插入、更新、删除数据 DML：增删改
    查询、条件、分组、分页 DQL：查询
    两张表关联查询 多表查询

    SQL 分类¶

    分类 作用 常用关键字
    DDL 定义库、表、字段 CREATE, ALTER, DROP, TRUNCATE
    DML 增删改数据 INSERT, UPDATE, DELETE
    DQL 查询数据 SELECT
    DCL 管理用户和权限 CREATE USER, GRANT, REVOKE
    TCL 控制事务 COMMIT, ROLLBACK

    建议：关键字大写，库名、表名、字段名保持项目内统一。

    数据库操作¶

    查看所有数据库¶

    1
    SHOW DATABASES;

    查看当前数据库¶

    1
    SELECT DATABASE();

    创建数据库¶

    1
2
3
    CREATE DATABASE IF NOT EXISTS `blog`
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

    选择数据库¶

    1
    USE `blog`;

    删除数据库¶

    1
    DROP DATABASE IF EXISTS `blog`;

    utf8mb4 比 utf8 更完整，能存 emoji 和更多特殊字符。新建业务库优先用 utf8mb4。

    表操作¶

    查看当前库的所有表¶

    1
    SHOW TABLES;

    查看表结构¶

    1
    DESC `user`;

    查看建表语句¶

    1
    SHOW CREATE TABLE `user`;

    创建表¶

    1
2
3
4
5
6
7
    CREATE TABLE `user` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '用户ID',
  `username` VARCHAR(50) NOT NULL UNIQUE COMMENT '用户名',
  `age` INT CHECK (`age` >= 0 AND `age` <= 120),
  `status` TINYINT NOT NULL DEFAULT 1 COMMENT '状态：1启用，0禁用',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
) COMMENT '用户表';

    添加字段¶

    1
    ALTER TABLE `user` ADD `email` VARCHAR(100) COMMENT '邮箱';

    修改字段类型¶

    1
    ALTER TABLE `user` MODIFY `email` VARCHAR(150);

    修改字段名和类型¶

    1
    ALTER TABLE `user` CHANGE `email` `user_email` VARCHAR(150);

    删除字段¶

    1
    ALTER TABLE `user` DROP `user_email`;

    修改表名¶

    1
    ALTER TABLE `user` RENAME TO `app_user`;

    删除表¶

    1
    DROP TABLE IF EXISTS `app_user`;

    清空表¶

    1
    TRUNCATE TABLE `app_user`;

    TRUNCATE 是清空整张表，不能加 WHERE。只想删除部分数据时用 DELETE。

    数据类型¶

    数值类型¶

    类型 用途
    TINYINT 状态、类型、布尔值
    INT 数量、年龄、普通编号
    BIGINT 主键 ID、订单号
    DECIMAL(p, s) 金额、精确小数
    FLOAT, DOUBLE 允许误差的小数

    金额优先用 DECIMAL，不要用 FLOAT 或 DOUBLE。

    字符串类型¶

    类型 用途
    CHAR(n) 固定长度编码
    VARCHAR(n) 用户名、标题、手机号
    TEXT 文章内容、备注
    JSON 半结构化扩展字段

    日期时间类型¶

    类型 用途
    DATE 日期
    TIME 时间
    DATETIME 日期时间，常用于业务时间
    TIMESTAMP 时间戳，会受时区影响

    创建时间¶

    1
    `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP

    更新时间¶

    1
    `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

    约束¶

    约束 关键字 作用
    主键 PRIMARY KEY 唯一标识一行
    自增 AUTO_INCREMENT 自动生成递增值
    非空 NOT NULL 字段不能为空
    唯一 UNIQUE 字段值不能重复
    默认值 DEFAULT 未指定时使用默认值
    检查 CHECK 限制字段取值范围
    外键 FOREIGN KEY 建立表之间的关联

    外键写法¶

    1
2
3
    ALTER TABLE `employee`
ADD CONSTRAINT `fk_employee_department`
FOREIGN KEY (`dept_id`) REFERENCES `department`(`id`);

    删除外键¶

    1
    ALTER TABLE `employee` DROP FOREIGN KEY `fk_employee_department`;

    外键能保证关系正确，但会增加写入和维护成本。小项目可以用，业务复杂时也常由应用层保证关系。

    DML：增删改¶

    插入一行¶

    1
2
    INSERT INTO `user` (`username`, `age`, `status`)
VALUES ('Jack', 18, 1);

    批量插入¶

    1
2
    INSERT INTO `user` (`username`, `age`, `status`)
VALUES ('Tom', 20, 1);

    1
2
    INSERT INTO `user` (`username`, `age`, `status`)
VALUES ('Lucy', 22, 1);

    如果网站复制按钮一次只复制一个代码块，批量插入可以按需复制多条。

    更新数据¶

    1
2
3
    UPDATE `user`
SET `age` = 19
WHERE `id` = 1;

    删除数据¶

    1
2
    DELETE FROM `user`
WHERE `id` = 1;

    删除前先确认范围¶

    1
2
3
    SELECT *
FROM `user`
WHERE `id` = 1;

    更新和删除一定确认 WHERE。没有 WHERE 会影响整张表。

    DQL：查询¶

    查询指定字段¶

    1
2
    SELECT `id`, `username`, `age`
FROM `user`;

    查询全部字段¶

    1
2
    SELECT *
FROM `user`;

    临时排查可以用 SELECT *，正式代码尽量写明确字段。

    字段别名¶

    1
2
    SELECT `username` AS `name`
FROM `user`;

    去重¶

    1
2
    SELECT DISTINCT `status`
FROM `user`;

    等值条件¶

    1
2
3
    SELECT *
FROM `user`
WHERE `id` = 1;

    范围条件¶

    1
2
3
    SELECT *
FROM `user`
WHERE `age` BETWEEN 18 AND 30;

    多选一¶

    1
2
3
    SELECT *
FROM `user`
WHERE `status` IN (1, 2);

    模糊匹配¶

    1
2
3
    SELECT *
FROM `user`
WHERE `username` LIKE 'J%';

    判断为空¶

    1
2
3
    SELECT *
FROM `user`
WHERE `email` IS NULL;

    判断非空¶

    1
2
3
    SELECT *
FROM `user`
WHERE `email` IS NOT NULL;

    NULL 不能用 = NULL 判断。

    统计数量¶

    1
2
    SELECT COUNT(*)
FROM `user`;

    求平均值¶

    1
2
3
    SELECT AVG(`age`)
FROM `user`
WHERE `status` = 1;

    分组统计¶

    1
2
3
    SELECT `status`, COUNT(*) AS `user_count`
FROM `user`
GROUP BY `status`;

    分组后筛选¶

    1
2
3
4
    SELECT `status`, COUNT(*) AS `user_count`
FROM `user`
GROUP BY `status`
HAVING `user_count` >= 10;

    WHERE 在分组前过滤行，HAVING 在分组后过滤聚合结果。

    多表关系¶

    关系 例子 设计方式
    一对多 部门和员工 在“多”的一方加外键
    多对多 学生和课程 建中间表，保存两边主键

    多表查询¶

    内连接¶

    1
2
3
    SELECT `e`.`name` AS `employee_name`, `d`.`name` AS `department_name`
FROM `employee` AS `e`
INNER JOIN `department` AS `d` ON `e`.`dept_id` = `d`.`id`;

    内连接只查两张表都能匹配上的数据。

    左连接¶

    1
2
3
    SELECT `e`.`name` AS `employee_name`, `d`.`name` AS `department_name`
FROM `employee` AS `e`
LEFT JOIN `department` AS `d` ON `e`.`dept_id` = `d`.`id`;

    左连接保留左表所有数据，右表匹配不到时显示 NULL。

    查没有部门的员工¶

    1
2
3
4
    SELECT `e`.*
FROM `employee` AS `e`
LEFT JOIN `department` AS `d` ON `e`.`dept_id` = `d`.`id`
WHERE `d`.`id` IS NULL;

    自连接¶

    1
2
3
    SELECT `e`.`name` AS `employee_name`, `m`.`name` AS `manager_name`
FROM `employee` AS `e`
LEFT JOIN `employee` AS `m` ON `e`.`manager_id` = `m`.`id`;

    UNION ALL¶

    1
2
3
    SELECT `username` FROM `user` WHERE `status` = 1
UNION ALL
SELECT `username` FROM `user_archive` WHERE `status` = 1;

    UNION 会去重，UNION ALL 不去重，通常更快。

    事务四大特性：

    特性 含义
    原子性 要么全成功，要么全失败
    一致性 事务前后数据规则正确
    隔离性 并发事务之间尽量互不干扰
    持久性 提交后的结果会持久保存

    查看隔离级别¶

    1
    SELECT @@TRANSACTION_ISOLATION;

    设置当前会话隔离级别¶

    1
    SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;

    MySQL InnoDB 默认隔离级别通常是 REPEATABLE READ。

    索引基础¶

    索引可以加快查询，但会占空间，并降低写入时的维护速度。

    创建普通索引¶

    1
2
    CREATE INDEX `idx_user_status`
ON `user` (`status`);

    创建联合索引¶

    1
2
    CREATE INDEX `idx_user_status_age`
ON `user` (`status`, `age`);

    查看索引¶

    1
    SHOW INDEX FROM `user`;

    删除索引¶

    1
2
    DROP INDEX `idx_user_status`
ON `user`;

    最左前缀¶

    如果索引是：

    1
2
    CREATE INDEX `idx_user_status_age`
ON `user` (`status`, `age`);

    容易用上索引：

    1
2
3
    SELECT *
FROM `user`
WHERE `status` = 1;

    也容易用上索引：

    1
2
3
    SELECT *
FROM `user`
WHERE `status` = 1 AND `age` > 18;

    不容易充分使用这个联合索引：

    1
2
3
    SELECT *
FROM `user`
WHERE `age` > 18;

    联合索引从最左边字段开始连续使用。

    容易导致索引失效¶

    对字段做函数计算：

    1
2
3
    SELECT *
FROM `user`
WHERE SUBSTRING(`username`, 1, 1) = 'J';

    左模糊匹配：

    1
2
3
    SELECT *
FROM `user`
WHERE `username` LIKE '%ack';

    字符串字段没有加引号，可能发生隐式类型转换：

    1
2
3
    SELECT *
FROM `user`
WHERE `phone` = 13800138000;
